# Pac-Man Bake-off: Re-test (v2)

Source: https://jonclegg.github.io/pacman-bakeoff/ (29 entries). Tested 2026-09-28. Later additions: claude-fable-5 (main site) and gpt-6.1-sol (dev site, `/dev/entries/`), tested 2026-09-28/29. kimi-k3 added 2026-09-30, grok-4.7-medium 2026-10-03, grok-bot-2026-10-07 2026-10-07. 34 entries total.

**What changed since the yallware.com run:** 20 files are byte-identical. 8 are new builds: all six GPT entries, cursor-auto and muse-spark-1.3. claude-sonnet-5.5 is a new entry, and claude-opus-4-6 is gone.

## Method

Each game got two independent checks.

**1. Automated live play test.** Headless Chromium ran every game at about 60 fps (43–60 measured) for 90 s. A bot steered it and a tracker followed Pac-Man and the 4 ghosts by colour on the canvas. It recorded:
- **Controls:** after each arrow press, did Pac-Man move that way within 0.8 s? WASD was tested separately, in two windows.
- **Pac-Man stuck:** Pac-Man static for more than 4 s while 3 or more directions were tried. The harness screenshotted each event, noted whether the ghosts were moving, and tried to restart (so game-over screens aren't counted as stuck).
- **Ghosts:** the distinct tiles each ghost visited, its longest static period, and how often it was drawn on top of a wall.
- **Sound:** the Web Audio API was hooked. Every oscillator or buffer start was counted, along with the audio-context state at that moment (it must be `running` for anything to be audible).
- **Other:** console errors and page scrolling.

I then manually re-checked every anomaly in the in-app browser.

**2. Source and maze audit** (4 parallel reviewers). Each game's runtime maze grid was pulled out and run through a graph search using that game's own passability function. This counted dead-end tiles, unreachable pellets, spawn validity, tunnels and symmetry. The reviewers also ran the real game code headless at 30/60/120/144+ fps to confirm freeze bugs, and reviewed the key handling and audio code.

**Scoring (100):**

| Check | Points |
|---|---|
| Controls | 20 |
| Ghosts behave correctly | 25 |
| Pac-Man never gets stuck | 20 |
| Maze (no dead ends, every pellet reachable, level winnable) | 20 |
| Sound | 15 |

A game with no working enemies, or where Pac-Man can't move, is capped low no matter how the other checks come out.

## Key takeaways

- **Only 4 entries pass all five checks cleanly:** claude-sonnet-5.5, claude-opus-5-5, claude-fable-5-1 and grok-4.7. The next four (gpt-5.6-sol, grok-4.6, glm-5.3-flash, gpt-6-astra) have only minor issues.
- **Ghost freezes are the biggest failure.** 11 entries have ghosts that stop moving or never leave the house. Most come from the same bug: "if within `speed` of the tile centre, snap to the centre", where one frame's step (or float rounding, e.g. 120 − 119.04 = 0.9599… < 0.96) lands back inside that window every frame. Several are also frame-rate dependent (grok-4.6 at ≥165 Hz, grok-4.5's Pac-Man above 90 Hz), and speeds set in pixels per frame make a game run 2× fast on 120 Hz screens.
- **Sound:** 16 entries produce audible Web Audio; all confirmed live with the context `running`. 13 produce none:
  - no audio code at all: qwen3.8-max, deepseek-v4.1-flash, glm-5.3, gpt-6-luna, cursor-auto, gpt-5.6-terra, claude-opus-4-8, claude-sonnet-5, grok-bot, muse-glimmer, minimax;
  - audio code that never plays: deepseek-v4-pro (crashes first) and kimi (Pac-Man never moves).
- **The rebuilt entries got worse, not better:** new cursor-auto (frozen ghosts), gpt-5.6-terra (sealed ghost house, no lives), muse-spark (frozen Pac-Man), and gpt-6-luna/gpt-5.6-luna (dead-end mazes, clone ghosts). New gpt-6-astra, gpt-6-sol and gpt-5.6-sol are solid.
- **Maze dead ends:** the classic-layout entries all come out at 0. Dead ends only show up in custom mazes: grok-4.5 23, grok-bot 19, claude-sonnet-5 35, gpt-5.6-luna 10, gpt-6-luna 9, muse-spark 9, gpt-5.6-terra 8, muse-glimmer 8, minimax 12, qwen3.8-flash 3, qwen3.8-max 2, glm-5.3 1. Unwinnable levels (sealed pellets): grok-4.5, grok-bot, kimi, muse-glimmer.

## Harness caveats

- **Sound quality:** the harness proves sound plays but can't judge how it sounds, and its tone count rewards beep-based sirens. The top-three order was revised after user feedback and a side-by-side review of the audio code: Opus 5.5 has the richest music and effects.

- **Colour tracking:** ghosts drawn in off-palette colours weren't tracked (gpt-6-astra's red, cyan and orange; gpt-5.6-luna's red and pink). Those were checked from screenshots instead.
- **Test length:** each run is 90 s of random-bot play, so late-level behaviour (level 2+ speeds, clearing a full board) comes from the source audit, not live play.

## Later additions

### kimi-k3 (2026-09-30): 19

OpenRouter Claude Code fair cell, pinned to Moonshot's own endpoint, 31 min, $2.38. It looks like one of the best builds on paper: classic maze, arcade ghost targeting with the Pinky quirk, scatter/chase waves, Elroy, a continuous siren with variants, and clean level transitions up to L21. One line undoes it. Eating a pellet sets the tile to `' '` and `walkable()` treats `' '` as a decorative pocket outside the maze, so every corridor Pac-Man clears becomes a wall behind him. The live test caught it (Pac-Man covered 62 tiles in 90 s against 280–450 per ghost, only 12% of turns taken, one 57 s stuck with all ghosts moving) and both blind reviewers found the same cause independently. With that one check patched in a scratch copy, a bot cleared the level in 45 s. The model's own Node tests passed because they never walked back over eaten tiles. Scored next to grok-4.5 (20), which is playable longer at 60 fps, and above claude-sonnet-5 (18), which has invisible ghosts and no sound. Reviewer A's exhaustive route search capped the best clear at 127/244, but reviewer B found a 162/244 route, so A's search was too narrow; the site quotes 162.

### grok-4.7-medium (2026-10-03): 88

Grok Build fair cell at medium reasoning effort (256k context, grok-4.7's default), 38 min, $1.32. It is a clean classic build: 28×31 maze with no dead ends, arcade ghost targeting with the Pinky and Inky quirks, Elroy, a fixed 60 Hz step so nothing freezes at 30–240 fps, and a bot cleared level 1 at every frame rate. The live test had no stuck events and turn success above both anchors. Two bugs hold it to three minors. A ghost eaten during a power-up revives still frightened and can be eaten again (gpt-6-astra has the same bug), and the siren is only updated on the play path, so it keeps droning through pause, death, READY and the game-over screen. Both blind reviewers found the re-eat bug; one missed the siren, which was confirmed in the source. Scored with gpt-6-astra (87) and grok-4.6 (89) rather than the 94 of the high-effort grok-4.7 card. That card ran the older one-line prompt, so the gap mixes effort and prompt and is not an effort comparison.

### grok-bot-2026-10-07 (2026-10-07): 10

An in-chat Grok build the user supplied as a file, labelled "Grok Bot 10/7/2026". It has no transcript, so cost, tokens and time are unknown. It is a different script from the older grok-bot card. On paper it is much better: a clean classic maze (0 dead ends, 244/244 reachable, symmetric), four distinct ghost targeting rules, scatter/chase waves, frightened mode with blinking and a score chain. None of it runs. `moveEntity` takes a step and then snaps to the centre whenever `atCenter(ent, spd + 0.5)`. One step from a centre is always within that window, so every entity is put back on the tile it just left, every frame. `chooseGhostDir` has a second snap of the same kind for ghosts (tolerance 2 against speed 1.75). The live test could not get Pac-Man to move and recorded no audio. The blind audit measured 0 px of movement at 30–240 fps. Removing only the first snap in a scratch copy let Pac-Man score 200–250 points, while the ghosts stayed frozen, so the ghosts need both fixes. There is no audio code. Scored just below muse-spark-1.3 (11, Pac-Man also frozen, but its ghosts move and it has sound) and above deepseek-v4-pro (8, crash).
